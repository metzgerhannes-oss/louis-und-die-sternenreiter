# Child Creator – Welt mit Louis weiterentwickeln

## Ziel

Das Kind soll sich nicht wie in einem Entwickler- oder Adminsystem fühlen. Eigene Ideen werden innerhalb der Geschichte an Louis erzählt.

## Kernfluss

```
Kind
→ Louis
→ Rückfragen
→ strukturierter Entwurf
→ Weltregelprüfung
→ Ideas-Datenbank
→ Erwachsenenreview
→ GitHub-Backlog
→ Anpassung/Freigabe
→ Umsetzung
→ Canon-Revision
```

## Beispiel

Kind:
> Auf einem Planeten soll alles riesig sein.

Louis fragt:
- Sind nur Pflanzen und Tiere riesig oder auch die Bewohner?
- Wie landen wir dort?
- Was können wir entdecken?
- Gibt es jemanden, dem wir helfen können?

Aus den Antworten entsteht ein strukturierter Vorschlag.

## Status innerhalb der Story

Technische Begriffe wie Issue oder Pull Request werden dem Kind nicht angezeigt.

Mögliche Louis-Texte:
- „Ich habe unsere Idee notiert.“
- „Die Sternenbauer schauen sie sich gerade an.“
- „Sie haben noch eine Frage.“
- „Unsere Idee ist jetzt Teil der Sternenkarte.“

## Freigabe

Mögliche Statuswerte:
- draft
- needs_details
- submitted
- under_review
- changes_requested
- approved
- rejected
- implemented
- canon

## GitHub

Ein GitHub-Issue wird erst serverseitig erzeugt, wenn die Idee den vorgesehenen Review-Status erreicht. Tokens bleiben ausschließlich serverseitig.

## Rückverfolgbarkeit

Jede freigegebene Weltänderung muss auf:
- die ursprüngliche Idee,
- Review-Änderungen,
- die umgesetzte Revision

zurückgeführt werden können.
